## 1. 이 방식이 하는 일 (한 줄)

**3단계(목차 구성)에서 소제목마다 "원본 IM의 몇 페이지"인지 번호를 직접 적으면**,
생성 시 그 페이지 내용이 그 소제목의 슬라이드로 만들어진다.

---

## 2. 화면(UX) 흐름

1. **1단계**: IM PDF 업로드 → 전체 페이지 텍스트/이미지 추출(`extracted_data.pages_text` = PDF 전체 쪽 텍스트, `parsed_pages` = 내용 페이지 구조).
2. **3단계 목차 구성**:
   - 왼쪽: 원본 IM 페이지 뷰어(한 장씩 넘겨봄).
   - 오른쪽: 목차 편집 — 대분류(목차1~4/5) + 소제목들.
   - **소제목 한 줄 = `[번호] [소제목] [페이지칸] [고정] [삭제]`**.
   - 사용자가 **페이지칸에 원본 페이지 번호를 직접 입력**(예: `8,9,11,10` · 순서·겹침 가능 · 범위 `16-19`).
   - `🤖 IM 전체 읽어 목차 자동 추출` 버튼: LLM이 원문 읽어 **대분류·소제목만** 자동 채움(★페이지는 안 채움 — 빈칸).
   - `🧹 기본 목차로 되돌리기`: 표준 목차(사모사채 개요/금융개요/사업개요/Appendix)로 초기화.
   - **고정 소제목**(1.1 본건 사모사채 개요 · 2.1 금융 구조도): 페이지 불필요, 항상 자동 생성.
3. **4단계 배치 확인**: 소제목별로 넣은 페이지를 순서대로 이미지로 미리 확인·수정.
4. **6단계 생성**: 목차·페이지 배치 순서 그대로 본문 PPT 생성.

## 3. 데이터 모델 (`st.session_state.toc_edit`)

```python
{
  "format": 4,                 # 대분류 개수(4 또는 5)
  "groups": [
    {"title": "사모사채 개요",
     "subs": [{"text": "본건 사모사채 개요", "pages": [], "fixed": True}]},
    {"title": "금융개요",
     "subs": [{"text": "금융 구조도", "pages": [], "fixed": True},
              {"text": "본건 기초자산 금융조건", "pages": [12,13], "fixed": False}]},
    ...
  ]
}
```
- `sub["text"]` = 소제목, `sub["pages"]` = **그 소제목에 넣은 원본 페이지 번호 리스트(순서 보존)**,
  `sub["fixed"]` = True면 원본 없이 자동 생성.

## 4. 코드 흐름 (핵심)

- **자동 목차(소제목만)**: `app._init_toc_edit_from_llm()` → `ai_slide_builders.generate_toc(full_text)`
  → `sections:[{title, subtitles[]}]`. subtitles를 subs로 만들되 **pages=[]**(사용자가 채움).
- **페이지 입력 UI**: `app.show_step_toc()` 안, 각 sub마다
  `sub["pages"] = _parse_pages(_p_raw, total)` (`_parse_pages`: '8,9,11,10,16-19' → [8,9,11,10,16,17,18,19], 정렬 안 함, total 초과·중복 제거).
- **생성**: `app.show_step4()` → `build_full_presentation(..., toc_groups=toc_edit["groups"])`
  → `page_builders.build_content_from_toc(prs, toc_groups, parsed_pages, ...)`:
  1. `by_page = {page_num: parsed_page}` (parsed_pages를 페이지번호로 색인).
  2. 각 group마다 섹션 divider 생성(무조건). gi==0→1.1, gi==1→2.1 자동.
  3. 각 sub의 `pages`를 돌며 `by_page[pnum]`을 찾아 `llm_structure.structure_page`로 구조화
     → `frame_builders.build_structured_slide`로 슬라이드 생성(적은 순서 그대로).
  4. 배정 페이지가 by_page에 없으면 그 페이지는 건너뜀(내용 없음).

- **주의(이 방식의 약점)**: 파싱이 어떤 페이지를 스킵하면 by_page에 없어서, 그 번호를 적어도
  내용이 안 나온다(그래서 파싱이 페이지를 최대한 살리는 게 중요 — 표/이미지 페이지 보존 로직 있음).

## 6. 키워드 방식으로 바뀌면 무엇이 달라지나 (예정)

- **안 바뀜(그대로 재사용)**: 생성 엔진(`build_content_from_toc`)은 여전히 **페이지 기반**.
  키워드는 내부적으로 "그 키워드가 가리키는 페이지들"을 들고 있어서, 키워드를 소제목에 연결하면
  결국 `sub["pages"]`가 자동으로 채워지는 구조로 갈 예정 → **되돌리기 쉽고 위험 적음**.
- **바뀜(UI만)**: 사용자가 페이지 번호를 직접 치는 대신, LLM이 뽑은 **키워드 칩을 소제목에 배치**.
